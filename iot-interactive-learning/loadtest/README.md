# Load / stress test — โหลดเทสต์ห้องเรียน

ยิงโหลดใส่ **เซิร์ฟเวอร์ของเราเอง** เพื่อดูว่ารับห้องเรียนได้กี่คน ก่อนจะช้าหรือพัง.
สคริปต์นี้พูด HTTP + SSE ชุดเดียวกับที่มือถือนักเรียนใช้จริง (`POST /api/room/actions`,
`GET /api/room/events`) — ไม่มี exploit ลับ ๆ มันแค่ทำสิ่งที่เบราว์เซอร์ทำ แต่ทำหลาย ๆ ครั้งพร้อมกัน.

> ป้องกันการใช้ผิดทาง: ยิงได้เฉพาะ host ในเครื่อง/วง LAN ส่วนตัว. ถ้าจะชี้ไปที่ host อื่น
> ต้องใส่ `--i-own-this-target` เอง (ยืนยันว่าเป็นเครื่องของเราและได้รับอนุญาต).

## รันยังไง

```bash
# 1) เปิดเซิร์ฟเวอร์ (โปรดักชันบิลด์)
npm run build
PORT=3999 node app.js            # พอร์ต 3000 อาจชนกับ OrbStack/Docker — ใช้พอร์ตว่างแทน

# 2) อีกเทอร์มินัล — ยิงโหลด
node loadtest/load-test.mjs classroom --target http://127.0.0.1:3999
# หรือผ่าน npm
npm run loadtest -- classroom --target http://127.0.0.1:3999
```

ยิงใส่ dev server ก็ได้ (`npm run dev`, พอร์ต 5173): `--target http://127.0.0.1:5173`.

## Scenarios

| scenario | จำลองอะไร |
|---|---|
| `smoke` | เช็คเร็ว ๆ ว่าทุกอย่างต่อกันได้ (นักเรียนไม่กี่คน ตอบ 1 ครั้ง) |
| `classroom` | **ห้องเรียนจริง**: เข้าห้อง → เปิด SSE ค้าง → ตอบพร้อมกัน → กดอิโมจิรัว (ตัวหลัก) |
| `join-storm` | นักเรียน N คนเข้าห้องพร้อมกันให้เร็วที่สุด — หาเพดาน / เจอ 429 ของ shared-IP limit |
| `answer-storm` | N คนกดตอบในหน้าต่าง broadcast 200ms เดียวกัน (เคสหนักสุด) |
| `emoji-flood` | N คนกดอิโมจิรัวตาม `--rate` เป็นเวลา `--duration` (โหลดเขียน + fan-out) |
| `read-flood` | ยิง `GET /health` รัว ๆ ที่ `--concurrency` วัด RPS ดิบ |
| `sse-hold` | เปิด event stream N เส้นค้างไว้ แล้ววัดว่า broadcast ไปถึงครบทุกเส้นไหม |
| `all` | รันทุก scenario ต่อกันแล้วสรุปรวม |

## Flags (หรือใส่เป็น env var ตัวใหญ่ เช่น `STUDENTS=100`)

| flag | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `--target` | `http://127.0.0.1:3000` | เซิร์ฟเวอร์ที่จะทดสอบ |
| `--students` | `40` | จำนวนนักเรียนจำลอง |
| `--duration` | `15` | วินาที (สำหรับ flood แบบจับเวลา) |
| `--concurrency` | `100` | worker ขนาน (read-flood) |
| `--rate` | `8` | อิโมจิต่อคนต่อวินาที (emoji-flood) |
| `--json <path>` | — | เขียนรายงานแบบเครื่องอ่านลงไฟล์ |
| `--i-own-this-target` | — | จำเป็นเมื่อชี้ไป host ที่ไม่ใช่ local |

## อ่านผลยังไง

- **rps / latency p50·p90·p99·max** — เร็วแค่ไหน และหางช้าแค่ไหนตอนโหลดขึ้น.
- **ok / throttled(429) / errors** —
  - `429` = **ปกติ ไม่ใช่บั๊ก**: rate limiter ทำงาน (`PER_STUDENT_LIMIT` 20 ครั้ง/3วิ ต่อ token,
    `SHARED_LIMIT` 1000 ครั้ง/3วิ ต่อ IP). บอตทุกตัวมาจาก IP เดียว (127.0.0.1) จึงชน shared bucket
    ง่าย — ตรงกับเคส "ทั้งห้องอยู่หลัง NAT โรงเรียน" ที่คอมเมนต์ใน `roomApi.js` พูดถึง.
  - `errors` (5xx / ต่อไม่ติด / timeout) = **ของจริงที่ต้องแก้**.
- ท้ายรายงานมีบรรทัดสรุป/เตือนอัตโนมัติ (มี error ไหม, p99 เกิน 1s ไหม, stream รั่วไหม).

## ค่าอ้างอิงที่วัดได้ (MacBook, โปรดักชันบิลด์, พอร์ต 3999)

- `classroom` 60 คน: 0 error, p99 ~29ms, ถือ SSE ครบ 60 เส้น.
- `join-storm` 2000: 998 ผ่าน / 1002 โดน 429 (ตรงเป๊ะกับลิมิต 1000/3วิ).
- `sse-hold` 150: broadcast ถึงครบ 150/150 เส้น ไม่มีรั่ว.
