# บทที่ 2: จากเซนเซอร์สู่สัญญาณ Digital / Analog

ฉบับออกแบบเนื้อหาและแผนจัดการเรียนรู้ สำหรับผู้เริ่มต้นที่ผ่านบทที่ 1 เรื่ององค์ประกอบ IoT, Sensor, Controller, Output และการเลือกเซนเซอร์แล้ว ใช้เวลาเสนอแนะ 80 นาที หรือแบ่งเป็น 2 คาบ คาบละ 40 นาที ปรับเวลาได้ตามผู้เรียน

## ผลการตรวจเนื้อหาเดิมและแนวทางปรับ

- ย่อเกริ่นนำเป็นภาพ IoT 3 ชั้น (Device → Network → Service) ด้วยระบบไฟอัตโนมัติ แล้วทบทวน Input/Output ผ่าน LDR/LED และ DHT11/พัดลม ก่อนเชื่อมสู่สัญญาณ
- แยก “สองระดับลอจิก” ออกจาก “จำนวนค่าที่แทนได้” และใช้ DHT11 ยืนยันว่าข้อมูลตัวเลขส่งแบบ Digital ได้
- ระบุขา AO/DO และรุ่นที่สมมติในโจทย์ ไม่เหมารวมว่า LDR หรือเซนเซอร์ดินเป็นสัญญาณชนิดเดียวทุกรุ่น
- แยกค่าดิบ ADC สัดส่วนของช่วงรหัส และหน่วยที่สอบเทียบแล้ว พร้อมข้อมูลทดลองให้ตีความ
- จัด PWM เป็นหัวข้อต่อยอดฝั่ง Output และจบบทด้วยการเตรียมค่าที่มีความหมายก่อนเขียน IF / ELSE
- เพิ่มกิจกรรมทดลองและอภิปราย 8 ชุด พร้อมแนวคำตอบ และคำถามโหวตในเว็บรวม 6 ข้อ

## จุดประสงค์และหลักฐานการเรียนรู้

| จุดประสงค์ | หลักฐานที่ใช้ตรวจ |
|---|---|
| อธิบายการส่งข้อมูลระหว่างเซนเซอร์กับบอร์ด | แผนภาพกิจกรรมเปิดบท |
| แยก Digital บิตเดียวกับหลายบิต | การทดลองเลขฐานสองและคำถาม DHT11 |
| อธิบาย Analog → ADC → ค่าดิบ | การทดลองบันได ADC และคำถามค่าดิบ 2048 |
| เลือกวิธีอ่านให้ตรงข้อมูลที่ต้องการ | คำถามจับคู่และแผนเครื่องบันทึกแสง |
| ตรวจความหมายของค่าก่อนตั้งเงื่อนไข | กิจกรรมนักสืบค่าดิน แผนกลุ่ม และบัตรออกจากห้อง |

## แผนเวลาและการใช้หน้าครู

| เวลา | เนื้อหา/กิจกรรม | การดำเนินการ |
|---|---|---|
| 0–8 นาที | 2.1–2.2 ภาพ IoT 3 ชั้น, Input/Output และสัญญาณ | ใช้เมนู Digital: 0 และ 1 เปิดเนื้อหา ให้คิดคู่และวาดเส้นทางข้อมูล |
| 8–25 นาที | 2.3–2.6 Digital, active-low, หลายบิต | ทดลองกราฟและรหัส จากนั้นเปิดกิจกรรม Digital และ Digital หลายบิต |
| 25–40 นาที | 2.7–2.9 Analog และ ADC | เปิดเนื้อหา Analog และ ADC ทดลอง 3/12 บิต แล้วตอบคำถาม Analog |
| 40–53 นาที | 2.10–2.12 ค่าดิบและข้อมูลทดลอง | เปิดเนื้อหาตีความค่าดิบ อภิปรายค่าดิน แล้วเปิดกิจกรรมของหัวข้อนี้ |
| 53–67 นาที | 2.13–2.15 จับคู่สัญญาณและ AO/DO | เปิดเนื้อหาเทียบสัญญาณสองแบบ ทำกิจกรรมคู่ แล้วเปิดคำถามจับคู่ |
| 67–77 นาที | 2.16–2.17 PWM และออกแบบการอ่านข้อมูล | กลุ่มเขียนแผน 5 นาที แลกเหตุผล แล้วเปิดกิจกรรมเลือกวิธีอ่าน |
| 77–80 นาที | 2.18 เชื่อมบทที่ 3 และบัตรออกจากห้อง | ตอบสามข้อด้วยคำของตนเองและส่งครู |

หากแบ่งสองคาบ ให้เริ่มคาบที่สองด้วยคำถาม “ก่อน ADC และหลัง ADC ต่างกันอย่างไร?” แล้วทบทวนสั้น ๆ จากผลคาบแรก

แต่ละเมนูในบทที่ 2 มีชุดสไลด์ของตนเอง: Digital 0/1 (2.1–2.4), Digital หลายบิต (2.5–2.6), Analog และ ADC (2.7–2.9), ตีความค่าดิบ (2.10–2.12), เทียบสัญญาณ (2.13–2.15) และเลือกวิธีอ่าน (2.16–2.18) ให้สอนแล้วเปิดกิจกรรมของเมนูนั้นตามลำดับ เวลาโหวตเริ่มเมื่อครูเปิดกิจกรรม

กิจกรรมทดลองและอภิปรายที่อยู่ในสไลด์เป็นการฝึกระหว่างเรียน ไม่สะสมคะแนนอัตโนมัติ นักเรียนทดลองบนเครื่องตนเองได้ ช่อง “เปิดแนวคำตอบหลังอภิปราย” เป็นเฉลยสำหรับตรวจด้วยตนเอง ควรตอบก่อนเปิด ส่วนคำถามโหวต 6 ข้อเก็บคะแนนในห้องเรียน และเปิดเฉลยเมื่อทุกคนตอบหรือหมดเวลา

## สื่อและการเตรียม

- หน้าครูและหน้าจอนักเรียนในเว็บ กระดาษหรือสมุดสำหรับแผนภาพและแผนกลุ่ม
- แบบจำลอง Digital, เลขฐานสอง และ ADC ที่อยู่ในเนื้อหา ไม่จำเป็นต้องต่อฮาร์ดแวร์จริง
- ก่อนเริ่ม ให้ทบทวนชื่อและหน้าที่ LDR, DHT11, PIR และเซนเซอร์ดิน หากยังจำไม่ได้ ใช้ภาพอุปกรณ์ในบทที่ 1 ประกอบ
- เน้นทุกครั้งว่าแบบจำลองไม่ใช่ผลวัดจากเซนเซอร์จริง และชุดข้อมูลดินในบทเป็นข้อมูลสมมติเพื่อฝึกตีความ

## เนื้อหาบทเรียนฉบับเต็ม

### Digital 0/1: สองระดับลอจิก

บทที่ 2 · ตอนที่ 1 / 6

จากบทที่ 1 ระบบ IoT ทำงานร่วมกัน 3 ชั้น: Device → Network → Service บทนี้เราจะดูว่าเซนเซอร์ส่งข้อมูลให้บอร์ดอย่างไร ผ่านสัญญาณ Digital และ Analog

| Device | Network | Service |
|---|---|---|
| LDR วัดแสง → ESP32 สั่ง LED | Wi-Fi ส่งค่าและสถานะไฟ | เก็บข้อมูลและแสดงในแอป |

**เมื่อเรียนจบส่วนนี้**

- ทบทวน Device / Network / Service ได้
- อธิบาย LOW/0 และ HIGH/1 ได้
- ตีความสถานะตามวงจร เช่น กด/ปล่อย หรือพบ/ไม่พบได้

#### 2.1 จาก Input / Output สู่สัญญาณ

ใน Device: Input รับข้อมูล → Controller ตรวจเงื่อนไข → Output ทำงาน เช่น LDR วัดแสง → ESP32 ตรวจว่ามืด → LED ติด

อีกตัวอย่างจากบทที่ 1: DHT11 วัดอุณหภูมิ → ESP32 ตรวจว่าร้อน → สั่งพัดลมผ่านวงจรขับ แล้วเซนเซอร์ส่งข้อมูลให้บอร์ดอย่างไร? เราจะเรียนผ่าน Digital และ Analog

**ใจความสำคัญ:** รู้หน้าที่อุปกรณ์แล้ว ต่อไปเรียนรู้รูปแบบสัญญาณที่ส่งระหว่างกัน

**คิดก่อนเรียน · 2 นาที**

1. ชี้ Input และ Output ในระบบไฟอัตโนมัติ
2. อธิบายว่าข้อมูลใดส่งเข้า ESP32

**คำถาม:** รู้แค่ว่า “มืดแล้ว” ต่างจากรู้ว่า “แสงลดลงเท่าไร” อย่างไร?

**แนวคำตอบ:** อย่างแรกบอกสถานะ อย่างหลังต้องมีค่าระดับ เราจึงต้องเลือกวิธีอ่านให้ได้รายละเอียดที่งานต้องการ

#### 2.2 สัญญาณคือสิ่งที่ใช้แทนข้อมูล

เซนเซอร์เปลี่ยนสิ่งที่ตรวจวัดเป็นสัญญาณให้บอร์ดอ่าน หัวข้อนี้เริ่มจาก Digital แบบไบนารี ซึ่งใช้ LOW และ HIGH แทนค่า 0 และ 1

ตัวอย่างโมดูล PIR: ขาสถานะบอกว่าพบการเคลื่อนไหวหรือไม่ บอร์ดอ่านสถานะแล้วตัดสินใจตามโปรแกรม โดยตรวจความหมายของ LOW/HIGH จากโมดูลที่ใช้

**ใจความสำคัญ:** เริ่มจากอ่านหนึ่งบิต แล้วตีความว่าแต่ละสถานะหมายถึงอะไร

#### 2.3 Digital: LOW และ HIGH

หนึ่งบิตมีได้สองค่า คือ 0 และ 1 วงจรแทนค่าด้วยช่วงแรงดันที่ยอมรับเป็น LOW และ HIGH ตามข้อกำหนดของอุปกรณ์ แรงดันจริงไม่จำเป็นต้องเป็น 0 V หรือค่าหนึ่งอย่างเป๊ะ ๆ และช่วงที่ยอมรับอาจต่างกันตามบอร์ด

ขาไฟเลี้ยงทำให้อุปกรณ์ทำงาน ส่วนขาสัญญาณส่งข้อมูล ดังนั้นอ่านได้ 0 ไม่ได้แปลว่าเซนเซอร์หรือบอร์ดดับ กราฟจำลองด้านล่างแสดงระดับลอจิก ไม่ใช่แรงดันจริง และการกดซ้ำเป็นการเพิ่มตัวอย่างตามเวลา ไม่ใช่เพิ่มระดับสัญญาณ

**ใจความสำคัญ:** LOW/HIGH เป็นระดับลอจิกสองระดับ ไม่ใช่สถานะไฟเลี้ยงของทั้งอุปกรณ์

**ทดลอง · ส่งสถานะ 2 นาที**

1. ทำนายกราฟเมื่อส่ง 0, 1, 1, 0
2. กดในแบบจำลองตามลำดับ แล้วเปรียบเทียบกับภาพที่ทำนาย

**คำถาม:** เมื่อส่ง 1 สองครั้งติดกัน กราฟจะขึ้นเป็น 2 หรือไม่ เพราะอะไร?

**แนวคำตอบ:** ไม่ขึ้นเป็น 2 กราฟยังเป็น HIGH สองตัวอย่างติดกัน เพราะ 1 เป็นค่าของแต่ละบิต ไม่ได้สะสมเป็นผลบวก

#### 2.4 ค่าลอจิกกับความหมายเป็นคนละเรื่อง

เรากำหนดให้ 1 หมายถึงกดปุ่ม และ 0 หมายถึงปล่อยได้ แต่บางวงจรเป็น active-low คือกดแล้วอ่านได้ 0 จึงต้องตรวจเอกสารหรือทดลองกดและปล่อยก่อนเขียนความหมายในโปรแกรม

เช่น วงจร A: ปล่อย = 0, กด = 1 ส่วนวงจร B: ปล่อย = 1, กด = 0 ทั้งสองยังเป็น Digital เหมือนกัน การอ่านค่าเพียงครั้งเดียวโดยไม่รู้วงจรจึงยังบอกไม่ได้ว่าอุปกรณ์ถูกกระตุ้นอยู่หรือไม่

**ใจความสำคัญ:** 1 ไม่ได้แปลว่าเปิดหรือพบเสมอไป ต้องรู้ข้อตกลงของวงจร

### Digital หลายบิต: จาก 0/1 สู่ตัวเลข

บทที่ 2 · ตอนที่ 2 / 6

หัวข้อก่อนหน้าใช้หนึ่งบิตบอกสองสถานะ คราวนี้เราจะนำหลายบิตมารวมกันเพื่อแทนตัวเลข เช่น 0101₂ = 5 ทุกบิตยังมีเพียง 0 หรือ 1 เหมือนเดิม

**เมื่อเรียนจบส่วนนี้**

- คำนวณจำนวนรูปแบบจากจำนวนบิตได้
- อ่านเลขฐานสอง 4 บิตเป็นจำนวนเต็ม 0–15 ได้
- อธิบายว่า DHT11 ส่งค่าตัวเลขด้วยข้อมูลดิจิทัลได้อย่างไร

#### 2.5 หลายบิตรวมกันแทนตัวเลขได้

1 บิตมี 2 รูปแบบ, 2 บิตมี 4 รูปแบบ และ 4 บิตมี 16 รูปแบบ สำหรับจำนวนเต็มไม่ติดเครื่องหมายจะแทนค่า 0–15 โดย n บิตมี 2ⁿ รูปแบบ

ในแบบจำลอง 4 บิต น้ำหนักจากซ้ายไปขวาคือ 8, 4, 2, 1 เช่น 0101₂ = 0×8 + 1×4 + 0×2 + 1×1 = 5 ส่วน 0110₂ = 6 ตัวอย่างนี้ใช้ฝึกเลขฐานสอง ไม่ใช่รูปแบบข้อมูลจริงของ DHT11

**ใจความสำคัญ:** เพิ่มจำนวนบิตแล้วแทนค่าได้มากขึ้น แต่แต่ละบิตยังมีสองค่า

**ทดลอง · รหัส 4 บิต 3 นาที**

1. เปลี่ยนบิตเป็น 0001, 0101 และ 1111 แล้วอ่านตัวเลขที่ได้
2. ลองสร้างเลข 6 และอธิบายด้วยน้ำหนัก 8, 4, 2, 1

**คำถาม:** 4 บิตแทนค่าได้กี่รูปแบบ และรูปแบบใดแทนเลข 6?

**แนวคำตอบ:** มี 16 รูปแบบ แทนจำนวนเต็มไม่ติดเครื่องหมาย 0–15 และ 0110₂ = 4 + 2 = 6

#### 2.6 DHT11: ถอดรหัสหลายบิตเป็นค่าที่วัด

PIR ในตัวอย่างให้สถานะพบ/ไม่พบ ส่วน DHT11 ส่งข้อมูลหลายบิตให้โปรแกรมถอดรหัสเป็นอุณหภูมิและความชื้น เช่น 28 °C จึงเป็น Digital เหมือนกัน แต่ให้รายละเอียดต่างกัน

อ่านขา DHT11 เป็น 0 หรือ 1 เพียงครั้งเดียวจะยังไม่รู้อุณหภูมิ ต้องรับชุดข้อมูลตามข้อตกลงการสื่อสาร ตัวเลขที่แสดงจึงไม่ได้แปลว่าสัญญาณเป็น Analog

**ใจความสำคัญ:** Digital ส่งได้ทั้งสถานะและตัวเลข ขึ้นกับวิธีจัดและตีความบิต

### Analog และ ADC: แปลงแรงดันเป็นตัวเลข

บทที่ 2 · ตอนที่ 3 / 6

Analog ใช้ระดับแรงดันที่ต่อเนื่อง ส่วน ADC แปลงแรงดันนั้นเป็นรหัสจำนวนเต็ม มาลองดูว่าจำนวนบิตเปลี่ยนความละเอียดของการอ่านอย่างไร

**เมื่อเรียนจบส่วนนี้**

- อธิบายสัญญาณ Analog ได้
- บอกหน้าที่ของ ADC ได้
- คำนวณจำนวนระดับและช่วงรหัสจากจำนวนบิตได้

#### 2.7 Analog: มีค่าระหว่างกลางอย่างต่อเนื่อง

แสงมีทั้งมืด สลัว และสว่างหลายระดับ วงจร LDR แปลงการเปลี่ยนความต้านทานเป็นแรงดันที่เปลี่ยนอย่างต่อเนื่องภายในช่วงทำงาน โมดูลเซนเซอร์ดินแบบ Analog ก็ส่งแรงดันตามการตอบสนองของวงจรเช่นกัน

Analog ไม่จำเป็นต้องเป็นคลื่นโค้งหรือเปลี่ยนตลอดเวลา แรงดันอาจคงที่อยู่ช่วงหนึ่งได้ คำว่าต่อเนื่องหมายถึงมีค่าระหว่างระดับได้ ไม่ใช่ส่งเร็วกว่า ใช้สายน้อยกว่า หรือแม่นยำกว่าเสมอ

**ใจความสำคัญ:** ดูวิธีแทนค่าของสัญญาณ ไม่ตัดสินจากรูปร่างกราฟเพียงอย่างเดียว

#### 2.8 ADC ทำอะไรระหว่างแรงดันกับโปรแกรม?

ADC ย่อมาจาก Analog-to-Digital Converter เมื่ออ่านค่า ADC จะวัดแรงดัน ณ ขณะหนึ่งแล้วจัดให้อยู่ในระดับที่แทนด้วยรหัสจำนวนเต็ม โปรแกรมจึงนำรหัสนั้นไปคำนวณได้ การอ่านซ้ำตามเวลาช่วยติดตามการเปลี่ยนแปลง

ก่อน ADC คือแรงดัน Analog หลัง ADC คือข้อมูลดิจิทัลที่แบ่งเป็นขั้น แรงดันสองค่าที่ใกล้กันอาจได้รหัสเดียวกันถ้าอยู่ในช่วงเดียวกันของ ADC การแปลงนี้ไม่ได้บอกเองว่าสิ่งที่วัดเป็นแสงหรือความชื้น

**ใจความสำคัญ:** ADC แปลงแรงดันเป็นรหัส ไม่ได้แปลงเป็นหน่วยของสิ่งที่วัดโดยอัตโนมัติ

#### 2.9 จำนวนบิตบอกจำนวนระดับ ไม่ใช่ความแม่นยำทั้งหมด

ADC n บิตมี 2ⁿ ระดับ และให้รหัส 0 ถึง 2ⁿ−1 ดังนั้น 3 บิตมี 8 ระดับ (0–7), 10 บิตมี 1024 ระดับ (0–1023), และ 12 บิตมี 4096 ระดับ (0–4095) แบบจำลองนี้ใช้ช่วงแรงดันสมมติเดียวกันเพื่อเปรียบเทียบจำนวนขั้น

เพิ่มบิตแล้วขั้นเล็กลง แต่ความแม่นยำยังขึ้นกับเซนเซอร์ วงจร สัญญาณรบกวน และการสอบเทียบ อีกทั้งรหัสเต็มสเกลของฮาร์ดแวร์จริงไม่จำเป็นต้องเท่ากับ 3.3 V ต้องตรวจช่วงวัดและการตั้งค่าของบอร์ด

**ใจความสำคัญ:** 12 บิต = 4096 ระดับ แต่ค่าสูงสุดเป็น 4095 เพราะเริ่มที่ 0

**ทดลอง · บันได ADC 4 นาที**

1. เลือก 3 บิต เลื่อนแรงดันทีละน้อย แล้วหาช่วงที่แรงดันเปลี่ยนแต่รหัสเท่าเดิม
2. สลับเป็น 12 บิตในแบบจำลอง และเปรียบเทียบความละเอียดของขั้น

**คำถาม:** ทำไมแรงดันเปลี่ยนเล็กน้อยแต่รหัสเดิม และ 12 บิตรับประกันว่าวัดถูกต้องกว่าเสมอหรือไม่?

**แนวคำตอบ:** แรงดันอาจยังอยู่ในช่วงรหัสเดียวกัน จำนวนบิตมากขึ้นช่วยแยกระดับได้ละเอียดขึ้น แต่ไม่รับประกันความถูกต้องหากเซนเซอร์หรือวงจรมีความคลาดเคลื่อน

### ตีความค่าดิบ: ตัวเลขนี้บอกอะไร?

บทที่ 2 · ตอนที่ 4 / 6

เมื่อ ADC ให้ตัวเลขแล้ว เรายังต้องหาความหมายของมัน หัวข้อนี้ใช้ข้อมูลทดลองแห้ง–เปียก ฝึกแยกค่าดิบออกจากหน่วยจริงก่อนตั้งเกณฑ์

**เมื่อเรียนจบส่วนนี้**

- แยกค่าดิบออกจากเปอร์เซ็นต์ความชื้นได้
- ตีความทิศทางค่าจากข้อมูลทดลองได้
- ระบุข้อมูลที่ต้องมีก่อนตั้งเกณฑ์ได้

#### 2.10 ค่าดิบไม่ใช่เปอร์เซ็นต์หรือหน่วยจริง

ค่าดิบ 2048 ของ ADC 12 บิตอยู่ประมาณกลางช่วงรหัส แต่ไม่ได้หมายถึงความชื้น 50% หรือ 2048 °C การคำนวณ 2048 ÷ 4095 × 100 ให้เพียงสัดส่วนของช่วงรหัส ADC ไม่ใช่เปอร์เซ็นต์ความชื้นในดิน

หากต้องการรายงานหน่วยจริง ต้องมีความสัมพันธ์ระหว่างค่าดิบกับสิ่งที่วัด และข้อมูลอ้างอิงที่เหมาะสม การทดลองกับดินแห้งและดินเปียกช่วยกำหนดระดับอ้างอิงเบื้องต้น แต่ยังไม่ใช่การวัดปริมาณน้ำในดินที่แม่นยำโดยอัตโนมัติ

**ใจความสำคัญ:** ระบุให้ชัดว่ารายงานค่าดิบ ดัชนีเทียบการทดลอง หรือหน่วยที่สอบเทียบแล้ว

#### 2.11 อ่านข้อมูลทดลองก่อนบอกว่าค่าสูงหมายถึงอะไร

สมมติทดลองเซนเซอร์ดินชุดเดิมได้ดินแห้ง 3300, 3400, 3500 และดินเปียก 1100, 1200, 1300 ค่าเฉลี่ยจึงเป็น 3400 และ 1200 ตามลำดับ ในชุดข้อมูลนี้ค่าที่สูงกว่าสัมพันธ์กับสภาพแห้งกว่า แต่ห้ามนำทิศทางนี้ไปใช้กับทุกรุ่นโดยไม่ทดลอง

ค่า 2300 อยู่กึ่งกลางระหว่างค่าเฉลี่ยอ้างอิงทั้งสอง แต่ยังสรุปไม่ได้ว่าเป็นความชื้นจริง 50% หรือถึงเวลารดน้ำ ต้องพิจารณาดิน ต้นไม้ ตำแหน่งติดตั้ง และเก็บข้อมูลเพิ่ม การอ่านซ้ำช่วยเห็นความแกว่งและหลีกเลี่ยงการตัดสินจากค่าเดียว

**ใจความสำคัญ:** ข้อมูลทดลองอธิบายทิศทางของค่าได้ แต่เกณฑ์ใช้งานต้องเหมาะกับโจทย์

**กิจกรรม · นักสืบค่าดิน 4 นาที**

1. จดช่วงค่าของดินแห้งและดินเปียกจากข้อมูลด้านบน
2. จัดค่า 1250 กับ 3350 ว่าใกล้กลุ่มใด แล้วเสนอข้อมูลที่ต้องรู้ก่อนตั้งเกณฑ์รดน้ำ

**คำถาม:** ค่า 3350 หมายถึงดินแห้งสำหรับทุกเซนเซอร์หรือไม่ และควรทำอะไรเมื่อเปลี่ยนโมดูล?

**แนวคำตอบ:** ไม่ใช่ ค่านี้ใกล้กลุ่มแห้งเฉพาะชุดทดลองที่กำหนด เมื่อเปลี่ยนโมดูลต้องตรวจเอกสารและทดลองกับสภาพอ้างอิงใหม่ เพราะช่วงค่าและทิศทางอาจเปลี่ยน

#### 2.12 เปรียบเทียบก่อนและหลังแปลงให้ชัด

ขา AO ส่งแรงดันที่ต่อเนื่องเข้า ADC ส่วนตัวเลข 0–4095 ที่โปรแกรมรับเป็นรหัสดิจิทัลหลังแปลงแล้ว การนำตัวเลขไปวาดกราฟให้ดูเป็นเส้นต่อกันไม่ได้เปลี่ยนชนิดของข้อมูลนั้น

เส้นทาง AO → ADC ต่างจาก DHT11 → รับชุดบิต → ถอดรหัส แม้ท้ายที่สุดทั้งสองทางจะให้ตัวเลขในโปรแกรมได้เหมือนกัน กิจกรรมทั้งหมดบนเว็บเป็นแบบจำลอง ไม่ได้อ่านแรงดันจากอุปกรณ์จริง

**ใจความสำคัญ:** ผลสุดท้ายเป็นตัวเลขเหมือนกัน แต่เส้นทางการอ่านอาจต่างกัน

### เทียบสัญญาณ: อุปกรณ์แต่ละตัวส่งอะไร?

บทที่ 2 · ตอนที่ 5 / 6

นำเซนเซอร์จากบทที่ 1 มาจับคู่กับวิธีอ่าน: อ่านสถานะ ถอดรหัสหลายบิต หรืออ่านผ่าน ADC โดยพิจารณารุ่นและขาที่ใช้

**เมื่อเรียนจบส่วนนี้**

- จับคู่เซนเซอร์กับวิธีอ่านได้
- แยกข้อมูลที่ได้จาก AO และ DO ได้
- เลือกข้อมูลสถานะหรือระดับให้ตรงโจทย์ได้

#### 2.13 สี่เซนเซอร์ สามวิธีอ่าน

ในตัวอย่างที่กำหนด: PIR ใช้ขาสถานะ Digital บิตเดียว, DHT11 ส่ง Digital หลายบิต, ส่วนโมดูล LDR และเซนเซอร์ดินที่เลือกขา AO ส่งแรงดัน Analog เข้า ADC ชื่อเซนเซอร์อย่างเดียวจึงยังไม่พอ ต้องระบุรุ่นหรือขาที่อ่านด้วย

ถามสามข้อก่อนเขียนโปรแกรม: สัญญาณที่ออกมาเป็นอะไร ต้องอ่านลอจิก/ถอดรหัส/ผ่าน ADC และค่าที่อ่านได้หมายถึงอะไร เซนเซอร์รุ่นอื่นที่วัดสิ่งเดียวกันอาจใช้การสื่อสารต่างกัน

**ใจความสำคัญ:** สิ่งที่วัดกับวิธีส่งข้อมูลเป็นคนละคุณสมบัติ

#### 2.14 AO และ DO บนโมดูลเดียวกัน

โมดูลบางรุ่นมี AO (Analog Output) ส่งแรงดันตามระดับที่วัด และ DO (Digital Output) ส่งสถานะจากวงจรเปรียบเทียบกับเกณฑ์ หากใช้ AO บอร์ดอ่านผ่าน ADC แล้วตั้งเกณฑ์ในโปรแกรมได้ หากใช้ DO บอร์ดอ่านสถานะตามเกณฑ์ของโมดูล

DO บอกเพียงว่าค่าอยู่ด้านใดของเกณฑ์ จึงย้อนหาระดับละเอียดจากสถานะเดียวไม่ได้ ต้องตรวจว่า HIGH หมายถึงด้านใด และไม่ได้มี AO/DO ครบทั้งคู่ในทุกโมดูล คำว่า Output บนขาเซนเซอร์หมายถึงสัญญาณที่ออกจากโมดูล แต่เซนเซอร์ยังเป็น Input ของระบบ

**ใจความสำคัญ:** ความสามารถของโมดูลและขาที่เลือกกำหนดข้อมูลที่บอร์ดจะได้รับ

**กิจกรรมคู่ · เลือกขาให้ตรงงาน 4 นาที**

1. สมมติว่าโมดูล LDR มีทั้ง AO และ DO
2. งาน A: รู้แค่ว่ามืดแล้ว งาน B: เก็บแนวโน้มแสงตลอดวัน เลือกขาและบอกเหตุผลของแต่ละงาน

**คำถาม:** งาน A ใช้ได้เพียง DO เท่านั้นหรือไม่ และทำไมงาน B ใช้ DO อย่างเดียวไม่พอ?

**แนวคำตอบ:** งาน A ใช้ DO ได้สะดวกเมื่อเกณฑ์บนโมดูลเหมาะสม หรือใช้ AO แล้วตั้งเกณฑ์ในโปรแกรมก็ได้ งาน B ต้องการระดับจึงเลือก AO ผ่าน ADC เพราะ DO เก็บได้เพียงสถานะผ่านเกณฑ์ ทั้งนี้ค่าจาก AO ยังไม่ใช่หน่วย lux จนกว่าจะมีการสอบเทียบที่เหมาะสม

#### 2.15 ต้องการตัวเลข ไม่ได้แปลว่าต้องใช้ Analog

หากต้องการอุณหภูมิห้องเป็นตัวเลข DHT11 ที่ส่งข้อมูลดิจิทัลก็ใช้ได้ภายในข้อจำกัดของอุปกรณ์ หากต้องการแนวโน้มดินจากโมดูล Analog ให้ใช้ AO ผ่าน ADC จึงควรเลือกจากชนิดข้อมูล ช่วงวัด ความละเอียด และความเหมาะสมกับงานร่วมกัน

ไม่มีข้อสรุปว่า Analog ให้ข้อมูลมากกว่า Digital เสมอไป การเทียบ AO กับ DO แบบบิตเดียวบนโมดูลเดียวกันเป็นคนละเรื่องกับการเทียบ Analog กับเซนเซอร์ Digital หลายบิตทั้งหมด

**ใจความสำคัญ:** ทั้ง Analog และ Digital หลายบิตใช้รายงานระดับได้

### เลือกวิธีอ่าน: ออกแบบระบบจากโจทย์

บทที่ 2 · ตอนที่ 6 / 6

ใช้ความรู้เรื่องสัญญาณออกแบบระบบหนึ่งงาน ระบุข้อมูลที่ต้องการ วิธีอ่าน วิธีตรวจความหมาย และ Output ก่อนนำไปเขียน IF / ELSE ในบทที่ 3

**เมื่อเรียนจบส่วนนี้**

- อธิบายการเปิด–ปิดและการปรับระดับด้วย PWM ได้
- เขียนแผนรับข้อมูลและสั่ง Output พร้อมเหตุผลได้
- บอกสิ่งที่ต้องตรวจสอบก่อนตั้งเงื่อนไขได้

#### 2.16 ต่อยอดฝั่ง Output: เปิด–ปิด กับ PWM

เมื่อข้อมูลเข้าบอร์ดแล้ว เราอาจสั่ง Output แบบเปิด–ปิด หรือปรับระดับ เช่น หรี่ LED ด้วย PWM (Pulse Width Modulation) ซึ่งสลับ LOW/HIGH อย่างรวดเร็วและปรับสัดส่วนเวลาที่เป็น HIGH ในหนึ่งคาบ เรียกว่าสัดส่วนหน้าที่หรือ duty cycle

ตัวอย่าง duty cycle 25% คือเป็น HIGH หนึ่งในสี่ของคาบ และ 75% คือสามในสี่ของคาบ สัญญาณยังเป็น Digital ไม่ใช่แรงดัน Analog ที่เรียบโดยตรง ในวงจร LED ที่ HIGH ทำให้ติด สัดส่วน HIGH มากขึ้นมักสว่างขึ้น แต่ความรู้สึกสว่างไม่จำเป็นต้องเพิ่มเป็นสัดส่วนตรง การควบคุมมอเตอร์ต้องใช้วงจรขับและวิธีที่เหมาะกับรุ่น

**ใจความสำคัญ:** สัญญาณ Input ไม่ได้บังคับชนิด Output และ PWM ยังเป็นสัญญาณดิจิทัล

#### 2.17 ออกแบบแผนอ่านข้อมูลก่อนเขียนเงื่อนไข

ตัวอย่างไฟทางเดินที่ต้องเก็บแนวโน้มแสง: เลือก LDR ขา AO → อ่าน ADC → ทดลองสว่าง/สลัว/มืดซ้ำหลายครั้ง → ระบุว่าค่าสูงหรือต่ำหมายถึงมืด → จึงตั้งเกณฑ์สั่งไฟ การส่งค่าขึ้นแอปเพิ่มการติดตามจากระยะไกล แต่ไม่ได้ทำให้ค่าที่วัดถูกต้องขึ้นเอง

เขียนแผนให้ครบว่า วัดอะไร ใช้เซนเซอร์/ขาใด ได้สัญญาณแบบใด อ่านด้วยวิธีใด และรู้ความหมายของค่าจากอะไร การเลือกชนิดสัญญาณไม่ใช่การแข่งขันว่าแบบไหนดีกว่า แต่ต้องตอบโจทย์ข้อมูลของงาน

**ใจความสำคัญ:** ก่อนสั่งงาน ต้องอธิบายที่มาและความหมายของค่าที่อ่านได้

**กิจกรรมกลุ่ม · แผนระบบ 5 นาที**

1. เลือกห้องเรียนหรือกระถางต้นไม้หนึ่งสถานการณ์
2. เขียนสิ่งที่วัด เซนเซอร์/ขา ชนิดสัญญาณ วิธีอ่าน และวิธีตรวจความหมาย
3. ให้เพื่อนถามหนึ่งข้อที่ช่วยตรวจว่าแผนยังขาดข้อมูลอะไร

**คำถาม:** ถ้าเพื่อนเขียนว่า “อ่านดินได้ 3000 จึงเปิดปั๊ม” ยังต้องรู้ข้อมูลอะไร?

**แนวคำตอบ:** ต้องรู้รุ่น/ขา ความละเอียดและช่วงวัด ทิศทางค่าจากการทดลอง และเหตุผลของเกณฑ์สำหรับดินหรือต้นไม้นั้น รวมทั้งกำหนดการหยุดปั๊มและวิธีทดสอบในบทถัดไป ไม่ควรถือว่า 3000 เป็นเกณฑ์มาตรฐาน

#### 2.18 สรุปบทที่ 2 และส่งต่อสู่บทที่ 3

บทที่ 1 ตอบว่าแต่ละอุปกรณ์ทำหน้าที่อะไร บทที่ 2 ตอบว่าข้อมูลเดินทางมาในรูปแบบใดและอ่านอย่างไร: Digital ใช้ LOW/HIGH ส่งสถานะหรือชุดบิต ส่วน Analog ใช้ค่าต่อเนื่องที่ต้องผ่าน ADC เมื่อต้องการให้บอร์ดนำไปคำนวณ

บทที่ 3 จะนำข้อมูลที่ตีความแล้วมาตั้ง IF / ELSE เช่น ถ้าค่าแสงต่ำกว่าเกณฑ์ให้เปิดไฟ มิฉะนั้นให้ปิด โดยสมมติว่าทดลองแล้วพบว่ามืดให้ค่าต่ำ เราจะตรวจกรณีต่ำกว่า เท่ากับ และสูงกว่าเกณฑ์ เพื่อให้เงื่อนไขตรงกับงาน

**ใจความสำคัญ:** อุปกรณ์ → สัญญาณ → ค่าที่มีความหมาย → เงื่อนไข → ผลลัพธ์

**บัตรออกจากห้อง · 3 นาที**

1. ตอบด้วยคำของตนเองสั้น ๆ ก่อนจบบท
2. ยกตัวอย่างอุปกรณ์ประกอบอย่างน้อยหนึ่งตัว

**คำถาม:** 1) Digital รายงานตัวเลขได้อย่างไร? 2) ค่าดิบ ADC ต่างจากหน่วยจริงอย่างไร? 3) ก่อนใช้ AO ตั้งเกณฑ์ต้องตรวจอะไร?

**แนวคำตอบ:** 1) รวมหลายบิตแล้วถอดรหัส เช่น DHT11 2) ค่าดิบเป็นรหัสของระดับแรงดัน ส่วนหน่วยจริงต้องมีความสัมพันธ์หรือการสอบเทียบ 3) ตรวจรุ่น ขา ช่วงวัด และทดลองสภาพอ้างอิงเพื่อรู้ทิศทางและช่วงค่าก่อนกำหนดเกณฑ์

## คำถามโหวต 6 ข้อและเฉลย

### ข้อ 1: Digital แบบไบนารี (30 วินาที)

Digital แบบไบนารีใช้กี่ระดับลอจิก?

A. 2 ระดับลอจิก (LOW/0 และ HIGH/1)
B. 10 สถานะ (0–9)
C. นับไม่ถ้วน (ค่าต่อเนื่อง)
D. ไม่มีสถานะที่แน่นอน

**เฉลย A:** หนึ่งบิตมีสองระดับลอจิก หลายบิตรวมกันแทนค่าได้มากกว่าสองค่า 0 ไม่ได้แปลว่าอุปกรณ์ไม่มีไฟเลี้ยง

### ข้อ 2: Digital ส่งอุณหภูมิเป็นตัวเลขได้อย่างไร? (45 วินาที)

DHT11 ส่งข้อมูลให้แสดง 28 °C ได้ เพราะเหตุใด?

A. ส่งแรงดัน 28 V เข้าบอร์ด
B. ส่งหลายบิตให้โปรแกรมถอดรหัส
C. เปลี่ยนเป็น Analog เมื่อค่าเกิน 1
D. อ่าน HIGH เพียงครั้งเดียว

**เฉลย B:** คำตอบคือส่งหลายบิตให้โปรแกรมถอดรหัส แต่ละบิตยังใช้ LOW/HIGH สองระดับ เมื่อรับครบตามรูปแบบจึงแปลเป็นตัวเลขได้ ไม่ใช่ส่ง 28 V และไม่ใช่อ่านสถานะเพียงครั้งเดียว

### ข้อ 3: ลักษณะของ Analog (30 วินาที)

สัญญาณ Analog แตกต่างจาก Digital อย่างไร?

A. มีแค่สถานะเปิดกับปิด (0 กับ 1)
B. มีค่าต่อเนื่อง เช่น แรงดันที่ค่อย ๆ เปลี่ยน
C. ส่งข้อมูลได้เร็วกว่ามาก
D. ใช้สายไฟน้อยกว่า

**เฉลย B:** ลักษณะที่ใช้แยกคือการแทนค่าของสัญญาณ ไม่ใช่ความเร็วหรือจำนวนสาย และค่าหลัง ADC เป็นรหัสดิจิทัลแล้ว

### ข้อ 4: นักสืบค่าดิบ ADC (45 วินาที)

อ่านเซนเซอร์ดินผ่าน ADC 12 บิตได้ 2048 แต่ยังไม่มีข้อมูลสอบเทียบ ข้อใดสรุปได้?

A. ดินมีความชื้นจริง 50% แน่นอน
B. ดินแห้ง ต้องเปิดปั๊มทันที
C. แรงดันต้องเท่ากับ 1.65 V ทุกบอร์ด
D. เป็นรหัสประมาณกลางช่วง 0–4095

**เฉลย D:** 2048 เป็นค่าดิบประมาณกลางช่วงรหัสของ ADC 12 บิตเท่านั้น ยังสรุปเปอร์เซ็นต์ความชื้น แรงดันที่แน่นอน หรือความจำเป็นในการรดน้ำไม่ได้ ต้องรู้ช่วงวัดและทดลองหรือสอบเทียบกับสิ่งที่วัดก่อน

### ข้อ 5: จับคู่เซนเซอร์กับวิธีส่งข้อมูล (60 วินาที)

กำหนดให้ LDR และเซนเซอร์ดินใช้ขา AO, PIR ใช้ขาสถานะ และ DHT11 ใช้ขาข้อมูล ข้อใดถูกทั้งหมด?

A. PIR: Digital บิตเดียว · DHT11: Digital หลายบิต · AO: Analog
B. PIR: Digital · DHT11 และ AO: Analog
C. PIR และ LDR AO: Digital · DHT11: Analog · Soil AO: Analog
D. ทั้งสี่เป็น Digital เพราะต่อกับบอร์ดเดียวกัน

**เฉลย A:** PIR ในโจทย์ให้สถานะหนึ่งบิต DHT11 ส่งข้อมูลหลายบิตให้ถอดรหัส ส่วนขา AO ที่ระบุส่งแรงดัน Analog ต้องผ่าน ADC การต่อกับบอร์ดเดียวกันไม่ได้ทำให้ชนิดสัญญาณเหมือนกัน และโมดูลบางรุ่นอาจมีขา DO ให้เลือกด้วย

### ข้อ 6: ออกแบบเครื่องบันทึกแสง (60 วินาที)

โมดูล LDR มี AO และ DO ถ้าต้องเก็บแนวโน้มระดับแสงตลอดวัน และปรับเกณฑ์เปิดไฟในโปรแกรม ควรเลือกแผนใด?

A. อ่าน DO แล้วแปลง 0/1 กลับเป็นระดับแสงละเอียด
B. อ่าน AO ผ่าน ADC ทดลองเทียบแสง แล้วเก็บค่าตามเวลา
C. เปลี่ยนเป็น PIR แล้วนับจำนวนครั้งที่ตรวจพบ
D. อ่าน AO เป็น LOW/HIGH อย่างเดียวแล้วเก็บค่า

**เฉลย B:** เลือก AO → ADC → ทดลองเทียบสภาพแสง → บันทึกค่าตามเวลา เพราะต้องการระดับเพื่อดูแนวโน้มและตั้งเกณฑ์เอง DO ให้เพียงสถานะผ่านเกณฑ์จึงกู้ระดับละเอียดกลับมาไม่ได้ ค่าที่บันทึกยังเป็นค่าดิบหรือดัชนีจนกว่าจะสอบเทียบเป็นหน่วยจริง

## ใบงานแผนกลุ่ม

ให้กลุ่มละ 2–4 คนเลือกโจทย์หนึ่งระบบ แล้วเติมตารางนี้

| สิ่งที่ต้องอธิบาย | คำตอบของกลุ่ม |
|---|---|
| ผู้ใช้และปัญหา | … |
| สิ่งที่ต้องวัด | … |
| ต้องการสถานะหรือค่าระดับ เพราะอะไร | … |
| เซนเซอร์ รุ่น/ขาที่สมมติใช้ | … |
| ชนิดสัญญาณ และวิธีอ่าน | … |
| วิธีทดลองเพื่อรู้ความหมายของค่า | … |
| Output ที่ต้องการ และข้อมูลที่จะส่งไปแอป | … |
| สิ่งที่ยังต้องหาคำตอบก่อนตั้ง IF / ELSE | … |

ตัวอย่างคำตอบ: ผู้ดูแลกระถางอยากเห็นแนวโน้มดิน เลือกเซนเซอร์ดินรุ่น Analog ขา AO อ่านผ่าน ADC เก็บข้อมูลหลายครั้งในดินแห้งและดินเปียกชุดเดิมเพื่อรู้ทิศทางค่า แสดงค่าหรือดัชนีอ้างอิงพร้อมเวลาในแอป และแจ้งเตือนเมื่อถึงเกณฑ์ที่ทดลองแล้วว่าเหมาะสม ยังต้องหาค่าเกณฑ์สำหรับต้นไม้และดินที่ใช้ ไม่ใช้ค่า 3000 เป็นมาตรฐานทุกระบบ

## เกณฑ์ประเมินและการช่วยผู้เรียน

ใช้เกณฑ์นี้ประเมินแผนกลุ่ม แยกจากคะแนนความเร็วในการโหวต

| ประเด็น | 2 คะแนน | 1 คะแนน | 0 คะแนน |
|---|---|---|---|
| ปัญหาและข้อมูล | ระบุปัญหาและข้อมูลได้ตรงกัน | ระบุได้บางส่วน | ข้อมูลไม่ตอบปัญหา |
| เซนเซอร์และขา | เลือกตรงสิ่งที่วัดและระบุขา/รูปแบบ | เลือกเซนเซอร์ได้แต่ไม่ชัดเรื่องขา | เลือกไม่ตรงสิ่งที่วัด |
| วิธีอ่าน | เลือกอ่านลอจิก/ถอดรหัส/ADC ตรงสัญญาณ | อธิบายได้แต่ยังขาดขั้นตอน | สับสนวิธีอ่าน |
| การตีความ | เสนอการทดลองและระบุข้อจำกัดของค่าดิบ | รู้ว่าต้องทดลองแต่ไม่บอกวิธี | ถือค่าดิบเป็นหน่วยจริงทันที |
| เหตุผลและการต่อยอด | เชื่อมข้อมูลกับ Output และสิ่งที่ต้องรู้ก่อนตั้งเงื่อนไข | อธิบายได้บางส่วน | ยังเชื่อมเหตุผลไม่ได้ |

เกณฑ์เสนอแนะ: อย่างน้อย 7/10 และหัวข้อวิธีอ่านกับการตีความต้องไม่เป็น 0 ผู้ที่ยังไม่ถึงเกณฑ์ให้แก้แผนจากข้อเสนอแนะแล้วอธิบายใหม่ คะแนนโหวตใช้กระตุ้นการมีส่วนร่วม ส่วนจำนวนข้อที่ถูกและเหตุผลใช้วิเคราะห์ความเข้าใจ

- ถ้าคิดว่า Digital มีได้แค่สองตัวเลข: กลับไปทดลอง 0000, 0001, 0010 และดูจำนวนรูปแบบ
- ถ้าสับสนค่าดิบกับเปอร์เซ็นต์: ให้เทียบ “50% ของช่วงรหัส” กับ “50% ความชื้น” แล้วระบุหลักฐานที่ต้องมี
- ถ้าเหมาว่า AO สูงแปลว่าสว่างหรือแห้งเสมอ: ให้เพื่อนเสนอวงจร/โมดูลต่างรุ่นและวิธีตรวจทิศทาง
- ผู้เรียนที่พร้อมต่อยอด: ถามว่าเมื่อค่าแกว่งใกล้เกณฑ์จะเกิดอะไร และเตรียมแนวคิดเกณฑ์เปิด/ปิดต่างกันสำหรับบทที่ 3
